# Data Product Operator v2.0.0

v2.0.0 turns a skill library into one system for data leaders, data product operators, and their teams. It has a person layer (skills for nine jobs), a team layer (Team Loop and five loops) and a company layer on the roadmap. dpm_os is now part of this repo as Team Loop.

## What's new

- **Glossary.** [GLOSSARY.md](../../GLOSSARY.md) defines data asset, data product, delivery surface, analytics agent, data product operator, data product team, consumer, team loop and strategy review. Skills and docs use these words.
- **First principles.** [Nine principles](../first-principles.md), where the sources disagree, a maturity model scored per use case, and credits.
- **Match grid.** [Nine jobs against nine source packs](../match-grid.md), with the cycle drawn above it and a note for every gap in this repo.
- **Analytics agents.** The [analytics-agent](../../skills/analytics-agent/SKILL.md) skill and four guides: a [reference architecture](../analytics-agents/reference-architecture.md) and three build routes. The golden-question eval is the core test.
- **New skills.** [metric-glossary](../../skills/metric-glossary/SKILL.md), [data-dictionary-grill](../../skills/data-dictionary-grill/SKILL.md), [data-product-retro](../../skills/data-product-retro/SKILL.md), [launch-and-adoption](../../skills/launch-and-adoption/SKILL.md) and [shipping-bridge](../../skills/shipping-bridge/SKILL.md). [grill-me-data](../../skills/grill-me-data/SKILL.md) now runs in rounds.
- **Five loops.** [decision-follow-up](../../skills/decision-follow-up/SKILL.md), [weekly-metric-review](../../skills/weekly-metric-review/SKILL.md), [data-quality-watch](../../skills/data-quality-watch/SKILL.md), [agent-eval-regression](../../skills/agent-eval-regression/SKILL.md) and [strategy-review](../../skills/strategy-review/SKILL.md). Each has a maker, a checker script, a state file and demo data. See the [loop pattern](../loop-pattern.md).
- **Team Loop.** The former dpm_os workspace, gates, weekly packet, decision log, validator and sample grader now ship in this plugin.
- **One check suite.** `python -m unittest discover -s tests` runs every check, and CI runs it on each pull request. It covers links, manifests, the glossary, the grid, adapted-skill credits, loop checkers, the grader, the Team Loop validator and containment.
- **Guardrails.** Commit hooks in `.githooks/` run the fast checks before each commit and the full suite before each push. A banned-word check reads its list from CLAUDE.md. Every loop checker must reject junk input without a crash, and the checkers share one helper module, `lib/loop_helpers.py`. [CONTRIBUTING.md](../../CONTRIBUTING.md) has the rules for outside changes.
- **Manifests.** Version 2.0.0. The descriptions now say "data leaders, data product operators, and their teams". New keywords: analytics-agents, data-mesh, claude-code.
- **README.** Rewritten: promise, cycle, 60-second quick start, a filled weekly packet, the grid, the person, team and company layers, the job index and credits.

## Upgrade

For a fork of data-product-operator:

1. Merge or rebase onto v2.0.0. Skill folders did not move. Only `skills/team-loop/` and `team-loop/` are new.
2. Run `python -m unittest discover -s tests`. If you changed a skill, fix what the checks report. Most findings are a broken link, an avoided glossary term, or an adapted skill with no `Source:` line.
3. If you bumped versions yourself, set both `.claude-plugin/plugin.json` and `.claude-plugin/marketplace.json` to the same semver.
4. Reinstall the plugin in Claude Code: `/plugin marketplace update data-product-operator`, then `/plugin install data-product-operator@data-product-operator`.

For a fork of dpm_os:

1. Move your changes to the paths in the table above. Edits to `.claude/skills/dpm-os/` go to `skills/team-loop/`.
2. Rename any `/dpm-os` references in your own docs to `/team-loop`.
3. Existing Team Loop workspaces need no change. The scaffold and validator are the same files. Run `python3 scripts/validate.py .` in each workspace to confirm.
4. To run the grader, use the new paths: `python3 team-loop/grader/data.py`, then `python3 team-loop/grader/grade.py demo`. The data file is now named for your DuckDB version, so `data.py` builds a fresh one once. You can delete the old `eunomia.duckdb`.
